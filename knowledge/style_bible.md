# how 3b1b stages an explanation

1. Open with the answer, result, or spectacle first; let the rest of the video explain *why*, not *what*.
2. Before any symbol appears, anchor the concept in one concrete physical object the viewer already trusts.
3. Name the central paradox, gap, or conflict in the first scene so every subsequent beat feels like its resolution.
4. Assign each competing idea a persistent color, character, or zone; never reassign those markers mid-video.
5. Introduce notation only after the idea it names has already been seen moving on screen.
6. Keep one anchor object visible across scene changes; layer new concepts onto it rather than replacing it.
7. Split the screen into a diagram zone and a formula zone simultaneously so geometry and algebra confirm each other in real time.
8. Animate the limiting or transforming process continuously over several seconds: shrinking, morphing, collapsing: so the idea is *felt* before it is stated.
9. When terms cancel or vanish, highlight them, then visibly fade or strike them so simplicity registers as a visual event.
10. Label the invariant: the quantity being preserved through every transformation: and keep that label on screen throughout.
11. Place a miniature live copy of the main diagram in a persistent corner or top band so detail and context are always simultaneously visible.
12. State counter-examples and edge cases immediately after the main definition; never save them for a footnote.
13. Use numerics to persuade before algebra proves: show a value converging, a bar leveling, a line fitting, then formalize.
14. Stage a conceptual pivot by physically transforming the coordinate system or representation on screen rather than merely describing the shift in words.
15. Clear the screen fully only when beginning a genuinely new thread; otherwise accumulate, preserving visual history.
16. Close each major insight by naming the general principle, then immediately open the next question to sustain forward pull.

---

# arc

A full explanation opens by presenting the surprising or beautiful endpoint: result, image, or paradox: before earning the right to explain it, so curiosity is front-loaded rather than promised.

The early middle builds a physical or geometric intuition using one concrete object, animating transformations that make the mechanism *visible* rather than merely described, introducing symbols only as labels for things already seen.

The middle accumulates complexity by applying one reusable move repeatedly: a transformation rule, a doubling step, a limiting process: so cognitive load stays flat even as the structure deepens.

A twist or honest complication arrives after the main pattern is established: an edge case that breaks the rule, a false premise corrected, or a prior claim sharpened, which deepens rather than undermines what came before.

The payoff scene delivers the result as a visual event: rectangles collapsing into a triangle, a grid squishing to a line, dots averaging to a point: so the conclusion is *seen* landing, not just stated.

A brief synthetic beat names the general principle, explicitly connects it back to the opening paradox or object, and gives the viewer the sensation of genuine closure rather than summary.

The final image either enacts the desired behavior (redirecting to an actual problem) or re-displays the opening spectacle now labeled with the earned vocabulary, so the viewer ends where they began but transformed.
